# Context

iFood argumenta que microinterações, acabamento e feedback alteram a percepção de qualidade do produto.

# Problem

Fluxos “funcionam” tecnicamente mas passam sensação de produto incompleto ou inseguro por falta de detalhe e feedback.

# Decision

Investir em detalhes de interação e acabamento como parte da qualidade percebida.

# Alternatives

Só features novas; polish só no final do roadmap (e nunca chega).

# Implementation

Microinterações e refinamentos de UI (detalhes no artigo).

# Validation

Relato qualitativo de percepção de qualidade.

# Results

Detalhe como alavanca de confiança e clareza.

# Trade-offs

Risco de over-polish / animações sem função (anti-padrão “cara de IA”).

# Extracted principles

- Feedback e acabamento afetam confiança.
- Detalhe deve servir à tarefa, não decorar.

# Context limitations

- Escala/branding iFood.
- Não define tokens do st-app-rn.

# Transferable principles

- `PRINCIPLE-UX-01`: feedback acionável e confirmação.
- Visual review: consistência e polish com tokens (`KB-DEC-001`).

# Non-transferable practices

- Animações gratuitas.
- Copiar linguagem visual iFood.
